### 1.5 浸泡测试（规则 3 的「不得卡顿闪退」）

**【实测】** 5 分钟连续播放，双路取证：进程/平面侧每 20 秒采样一次，
JS 侧每 2 秒一条 `poll tick`（共 149 条）。

**进程与平面（`/tmp/soak.sh` → `/tmp/soak.out`，14 条采样）**

```
15:18:00 t=0s   pid=679 plane=1 err=0
15:18:20 t=20s  pid=679 plane=1 err=0
...
15:21:20 t=200s pid=679 plane=1 err=0
15:21:40 t=220s pid=679 plane=0 err=0
15:22:00 t=240s pid=679 plane=0 err=0
15:22:20 t=260s pid=679 plane=0 err=0
```

**JS 侧播放统计（149 条 tick 的聚合）**

| 指标 | 实测值 |
| --- | --- |
| `state` | 全程 `playing`（149/149） |
| `frames` 增量 | 每 2 秒 +60/+61，均值 60.3 → **30.16 fps** |
| `stall` | 均值 17.8ms，最大 49ms（远小于判卡顿的 80ms 阈值） |
| `ab`（音频字节） | 24 912 → 2 408 381，**全程单调递增**（差值 2 383 469） |
| `plane` / `alive` | 全程 1 / 1 |
| `recover`（自愈触发） | 0/3 —— 一次都没触发 |

`plane` 在 t=220s 之后变 0 是**正常退出**：本轮播放的是 300 秒的探针，
`[bili] PROBE done` 之后 `onBack()` 关闭会话，视频平面自然释放，
`pid` 仍是 679（进程没退出）。这里刻意把 `source died` 从错误判据里剔除，
因为**它同时是「ffmpeg 到达 `-t` 时间上限后正常结束」的信号**——早期版本把
正常结束算成故障，制造过一次假警报。

### 5.1 浸泡脚本（可直接复用）

```sh
#!/bin/sh
# 5 分钟浸泡：每 20 秒一条。判据只看真故障，不把正常结束算错。
OUT=/tmp/soak.out
rm -f $OUT
i=0
while [ $i -lt 15 ]; do
  P=$(pidof miniapp)
  A=$(grep -c "Esmart1-win0" /sys/kernel/debug/dri/0/summary 2>/dev/null)
  # 注意：不要把 "source died" 算进 err —— 它同时是 ffmpeg 到达 -t 上限后
  # 正常结束的信号，混进去会让每次正常播完都报一次假警（踩过）。
  E=$(grep -ac "bus error\|OPEN failed\|first frame failed\|plane lost\|no frame in" /tmp/pb2.log 2>/dev/null)
  F=$(grep -ac "first frame on screen" /tmp/pb2.log 2>/dev/null)
  S=$(grep -ac "seek(restart) done" /tmp/pb2.log 2>/dev/null)
  echo "$(date +%H:%M:%S) t=$((i*20))s pid=$P plane=$A err=$E frames=$F seeks=$S" >> $OUT
  i=$((i+1))
  sleep 20
done
echo "DONE" >> $OUT
```

后台运行（**必须 `nohup setsid` + 重定向，否则 adb shell 断开会被杀**）：

```sh
nohup setsid sh /tmp/soak.sh </dev/null >/dev/null 2>&1 &
```

### 5.2 iOS 风格的「看起来没问题」不算证据

本项目踩过的假阳性，写在这里提醒复核者：

| 曾经的结论 | 实际真相 |
| --- | --- |
| 「暂停后视频平面已缩到 1×1，键盘不被遮挡」 | 探针在 hide 后 2.5s 就 restore，restore 触发了一次 seek 重建管线，**顺带**把矩形改对了。暂停态其实一次都没生效。 |
| 「seek 首帧到达，耗时 201ms」 | 那是**旧管线**还在出帧，新管线根本没建好。判据只看帧数增长会被骗。 |
| 「单 FIFO 64KB 背压死锁」 | 屏幕被我自己关掉了（`hal-screen off`），JS 自动息屏暂停。真死锁不会连 `pos` 都停在整数上。 |

结论：**每条判据都要能用「外部可观测的物理事实」交叉验证**
（DRM 平面的 `dst: pos[x,y] rect[w x h]`、平面 buffer 变化次数、
`/proc/<pid>/status` 的线程状态），不能只看 JS 侧返回 `{ok:true}`。
